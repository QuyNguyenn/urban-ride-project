# Architecture Decision Records

Use sequential filenames such as `0001-project-hub-data.md`. Clearly identify whether an ADR concerns the product or project hub. ADRs explain decisions; task delivery remains in tracking.

Each ADR contains:
- Status: `proposed`, `accepted`, or `superseded`.
- Scope: `product` or `project-hub`.
- Context.
- Options considered.
- Decision.
- Trade-offs/consequences.

Keep unconfirmed product decisions proposed. Accepted routine hub implementation choices may be made within the assigned scope. When superseding a decision, link both records and preserve the original rationale.
